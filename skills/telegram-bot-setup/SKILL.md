# Telegram-бот для воронки

> Используете другой сервис, а не ChatPlace? Не отказывайтесь: набор адаптируется, см. `docs/ADAPTING.md` в корне репозитория.

Бот решает три задачи: принять человека из Instagram по ссылке с кодом (`https://t.me/your_bot?start=gayd_ig`),
убедиться, что он подписан на канал, и выдать материал. Логика бота собирается в ChatPlace (`chatplace-funnels`),
а этот скилл описывает всё вокруг: сам бот, канал, права и ссылки.

Секреты – только в переменных окружения (образец в `.env.example`): `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHANNEL_ID`.
Токен нельзя присылать в чаты, коммитить и печатать в логи. Скрипт `scripts/tg_api.py` маскирует токен в ошибках.

## 1. Создать бота в @BotFather

1. Откройте в Telegram @BotFather, команда `/newbot`.
2. Имя бота (любое, видно людям) и username (латиница, заканчивается на `bot`, например `your_bot`).
3. BotFather пришлёт токен вида `123456789:AA…`. Положите его в `.env` как `TELEGRAM_BOT_TOKEN`.
4. По желанию: `/setuserpic` (аватар), `/setdescription` (текст на экране перед нажатием Start),
   `/setabouttext` (короткое описание профиля).
5. Проверка: `python3 skills/telegram-bot-setup/scripts/tg_api.py me` выводит `@your_bot id=…`.

Если токен попал не туда – `/revoke` у BotFather выдаст новый, старый перестанет работать.
Один бот – одна роль: не используйте токен чужого бота и не делите токен между сервисами.

## 2. Подключить бота к ChatPlace

В кабинете ChatPlace подключите Telegram-бота по токену. Точное место в интерфейсе и требования тарифа –
проверьте в документации ChatPlace. В списке API-инструментов есть `bots_register_telegram` (регистрация бота) и
`bots_update_telegram` (смена токена); их аргументы в исходных материалах не описаны, поэтому в скриптах репозитория
эти вызовы не используются.

После подключения: `python3 skills/chatplace-funnels/scripts/chatplace.py bots` – найдите Telegram-бота и запишите его id
в `CHATPLACE_TG_BOT_ID`.

Про ключи: в исходных материалах у Instagram-пространства и Telegram-пространства ChatPlace были разные ключи, и ключ одного не
видел бота другого («нет доступа» по одному ключу не вывод). Проверьте, как у вас, и при необходимости используйте
`--key-env` (см. `chatplace-funnels`).

Ограничение Telegram-ботов в ChatPlace: триггеров по комментариям нет, только `messageContains`, `messageEquals`,
`messageAnyValue`. Механику «напиши слово под постом» делает Instagram-часть; в Telegram человек приходит по реф-ссылке.

## 3. Канал и права бота

1. Создайте канал (или возьмите свой). Если контент закрытый – делайте его приватным: вход только по инвайт-ссылке.
2. Канал -> Управление каналом -> Администраторы -> добавьте бота. Достаточно права «Добавление подписчиков»
   (`can_invite_users`). Без прав администратора проверка подписки не работает **ни у кого**: бот не видит участников.
3. Узнайте id канала (`-100XXXXXXXXXX`): список каналов, которые видит ChatPlace, возвращает инструмент
   `automations_triggers_list_telegram_channels`. Id положите в `TELEGRAM_CHANNEL_ID`.
   (Через `getUpdates` брать id не стоит: пока у бота настроен вебхук ChatPlace, `getUpdates` недоступен.)
4. Проверка: `python3 skills/telegram-bot-setup/scripts/tg_api.py check-admin` – скажет, администратор ли бот и есть ли право приглашать.

## 4. Проверка подписки в воронке

В воронке ставится блок-условие «подписан на канал» (`check_subscription` с `chatId: [-100…]`); шаблон
`checkSubscription` в `automations_quick_setup` создаёт его сам, а `gate.py` дописывает тексты и кнопки.
Схема и нюансы – в `chatplace-funnels`. Для ручной проверки конкретного человека:

```bash
python3 skills/telegram-bot-setup/scripts/tg_api.py is-subscribed --user-id 123456789
```

Статусы `creator`, `administrator`, `member` (и `restricted`) считаются подпиской; `left` и `kicked` – нет.

## 5. Пригласительные ссылки: имя на каждый источник, member_limit 99999

Правила:

1. **Своя ссылка на каждый источник трафика** (на каждое кодовое слово и каждую площадку) и **имя ссылки = источник**
   (`gayd-ig`). Тогда по Telegram видно, сколько человек пришло по каждой ссылке.
2. **`member_limit` всегда 99999.** Ссылки без лимита иногда ломаются (правило из практики авторов). Telegram принимает значения 1–99999.
3. Имя ссылки – до 32 знаков.
4. Не создавайте ссылки руками в приложении, если ведёте учёт: имя и лимит легко забыть. Создавайте командой:

```bash
python3 skills/telegram-bot-setup/scripts/tg_api.py invite --name gayd-ig --registry invites.json
# gayd-ig https://t.me/+AbCdEfGh
```

Реестр `invites.json` хранит пары «источник -> ссылка»; повторный вызов с тем же именем ссылку **не** пересоздаёт, а выводит
сохранённую с пометкой `(already)`. Ссылка идёт в кнопку «Подписаться на канал» (поле `invite` в `gate.example.json`).

Реестр `invites.json` с реальными ссылками не коммитьте: он в `.gitignore`.

Учёт подписок по источникам внутри Telegram: Управление каналом -> Пригласительные ссылки показывает ссылки с именами и
числом вступивших. Свою таблицу или сервис, который ловит события `chat_member` с полем `invite_link`, при желании
пишут отдельно – в этом репозитории такого сервиса нет.

## 6. Меню бота на /start (по желанию)

Одна воронка с триггером `messageContains: ["/start"]`: одно сообщение с баннером и inline-кнопками и по одному блоку-карточке
на каждую кнопку. Кнопка, которая должна запустить другую воронку, ведёт на action-блок `run_automation`. Карточка без
входящей кнопки – мёртвый контент; после сборки проверьте `get_detail`.

## 7. Тест

1. С чистого аккаунта (или удалив чат с ботом) откройте `https://t.me/your_bot?start=gayd_ig`, нажмите Start.
2. Не подписываясь, нажмите «Получить…» – должно прийти «Пока не вижу подписки» и те же две кнопки.
3. Подпишитесь по кнопке (вступление идёт по именной ссылке), нажмите «Получить…» – приходит выдача.
4. Проверьте, что кнопки открывают ссылку сразу, без `l.chatplace.io`.
5. Прочитайте переписку: `chatplace.py` не умеет её выводить, используйте `chats_messages` (см. `chatplace-funnels`).
   Секунды между сообщениями показывают, был ли «гейт» или всё улетело пачкой.
